# PRD: 管理者介面 AI 模型

## Executive Summary

本專案旨在為高速公路交通管制系統的管理者介面創建專用的 AI 模型服務。該服務將使用與駕駛者介面相同的 Ollama qwen2.5:7b 模型,但透過獨立部署和客製化的提示詞設計,為交通管理人員提供系統層級的決策支援、多車輛協調建議、政策執行指引和即時分析能力。

**核心價值主張:**
- 提供系統層級的交通洞察與決策建議
- 支援管制策略制定與執行
- 基於真實資料的智能分析與預測
- 雙模式互動:自由對話與智能建議

## Problem Statement

### 問題描述

目前系統中的 AI 模型(ollama_chat.py)主要針對駕駛者設計,其提示詞強調個人導航建議、替代路線和單一車輛的最佳化策略。然而,管理者介面需要的是:

1. **宏觀視角**: 需要系統整體交通狀況分析,而非單一車輛建議
2. **決策支援**: 需要評估不同管制策略的影響和成本效益
3. **政策導向**: 需要符合交通政策和規則的建議,而非僅考慮用戶便利性
4. **多維度分析**: 需要整合震波偵測、預測模型、交通指標等多元資料

### 為何現在重要

管理者介面(ControlCenter.tsx)已經建構完成,包含:
- 系統狀態監控
- 即時交通指標
- AI 決策建議面板
- RAG 聊天機器人整合

但目前缺乏專為管理者設計的 AI 後端服務,導致:
- 無法提供適合管理決策的建議
- AI 回應偏向個人導航而非系統管制
- 未能充分利用管理者可獲取的完整資料
- 缺乏對政策和規則的考量

## User Stories

### 主要用戶角色

**角色 1: 交通控制中心管理員**
- 負責監控高速公路即時交通狀況
- 需要根據 AI 建議決定是否實施匝道管制、車道管制等措施
- 需要評估不同管制策略的成本與效益

**角色 2: 交通分析師**
- 負責分析交通趨勢和預測未來壅塞
- 需要理解震波成因和影響範圍
- 需要產生報告和數據洞察

**角色 3: 系統管理員**
- 負責系統健康狀態監控
- 需要了解 AI 模型效能和準確度
- 需要調整系統參數和配置

### 詳細使用情境

**情境 1: 緊急事件處理**
```
管理員發現國道 1 號出現嚴重交通震波
→ 透過 AI 智能助手詢問:「針對國道 1 號台北-桃園段的震波,建議採取什麼管制措施?」
→ AI 分析震波強度、影響範圍、預估持續時間
→ 提供具體建議:匝道管制位置、建議管制時長、預期效果
→ 管理員評估後決定執行建議
```

**驗收標準:**
- AI 回應時間 < 5 秒
- 建議包含至少 3 種管制選項
- 每個選項包含預期效果、成本估算、實施難度
- 建議符合交通法規和政策

**情境 2: 即時諮詢與決策支援**
```
管理員查看儀表板發現壅塞程度上升
→ 點擊「AI 智能助手」按鈕開啟聊天視窗
→ 輸入:「目前的壅塞熱點在哪裡?原因是什麼?」
→ AI 整合即時交通資料、震波偵測、預測結果
→ 提供結構化分析:熱點位置、成因分析、趨勢預測
→ 管理員根據分析制定應對策略
```

**驗收標準:**
- 聊天介面支援連續對話,保留上下文
- AI 能正確引用即時資料(站點速度、車流量等)
- 回應結構清晰,使用繁體中文
- 支援追問和細節詢問

**情境 3: 主動 AI 建議**
```
系統偵測到多個震波同時發生
→ AI 自動分析當前狀況
→ 在「AI 決策建議」面板產生建議卡片
→ 每個建議包含:標題、描述、優先級、預期影響、信心度
→ 管理員點擊「執行建議」按鈕
→ 系統執行相應管制措施
```

**驗收標準:**
- AI 建議自動產生,無需人工觸發
- 建議按優先級排序(高/中/低)
- 每個建議有明確的可執行性
- 執行後能追蹤實際效果

## Requirements

### Functional Requirements

#### FR1: 獨立的管理者 Ollama 服務
- **FR1.1**: 建立獨立的 Ollama 客戶端模組 `admin_ollama_client.py`
- **FR1.2**: 使用相同的 qwen2.5:7b 模型
- **FR1.3**: 配置獨立的連線設定和超時參數
- **FR1.4**: 支援非同步請求和流式回應

#### FR2: 管理者專用提示詞系統
- **FR2.1**: 設計系統提示詞(System Prompt),強調:
  - 系統層級決策而非個人導航
  - 政策與規則優先考量
  - 多車輛協調與整體最佳化
  - 成本效益分析
- **FR2.2**: 提示詞需涵蓋的資料類型:
  - 即時交通指標(總車流、平均速度、壅塞程度)
  - 震波偵測資料(位置、強度、影響範圍、持續時間)
  - 預測分析結果(MT-STNet 模型輸出)
  - 系統狀態(監測站點、預測準確度、系統負載)
- **FR2.3**: 支援不同類型的管理查詢:
  - 管制建議查詢
  - 替代道路指引策略
  - 預測分析解讀
  - 趨勢分析與報告

#### FR3: 管理者聊天 API
- **FR3.1**: 建立 `/api/admin/chat` 端點
- **FR3.2**: 接收參數:
  ```python
  {
    "message": str,           # 管理員問題
    "system_data": {          # 系統資料
      "traffic_metrics": {...},
      "shockwaves": [...],
      "predictions": [...],
      "alerts": [...]
    }
  }
  ```
- **FR3.3**: 回應格式:
  ```python
  {
    "response": str,          # AI 回應
    "model": str,             # 模型名稱
    "timestamp": str,         # 時間戳記
    "data_sources": [str],    # 使用的資料來源
    "confidence": float       # 信心度
  }
  ```
- **FR3.4**: 支援對話歷史保留(最近 5 輪對話)

#### FR4: AI 智能建議生成
- **FR4.1**: 建立 `/api/admin/ai-recommendations` 端點
- **FR4.2**: 自動分析當前交通狀況
- **FR4.3**: 生成結構化建議:
  ```python
  {
    "id": str,
    "priority": "high" | "medium" | "low",
    "type": "traffic_control" | "route_guidance" | "emergency_response",
    "title": str,
    "description": str,
    "expected_impact": str,
    "estimated_cost": float,
    "implementation_time": int,  # 分鐘
    "confidence": float,
    "rationale": str             # AI 建議理由
  }
  ```
- **FR4.4**: 基於真實資料動態生成,非靜態模擬資料

#### FR5: 資料整合與上下文建構
- **FR5.1**: 整合來自不同 API 的資料:
  - `/api/admin/system-status`
  - `/api/admin/traffic-metrics`
  - `/api/shockwave/active`
  - `/api/prediction/*`
- **FR5.2**: 建構結構化的上下文資訊供 AI 使用
- **FR5.3**: 資料過濾與優先級排序(最相關的資訊優先)

### Non-Functional Requirements

#### NFR1: 效能需求
- **NFR1.1**: AI 回應時間 < 5 秒(非流式)
- **NFR1.2**: 流式回應首字節延遲 < 1 秒
- **NFR1.3**: 支援同時 10 個管理者並發請求
- **NFR1.4**: 大量資料(>1000 站點)時仍能快速回應

#### NFR4: 可維護性需求
- **NFR4.1**: 提示詞獨立配置,不需修改程式碼
- **NFR4.2**: 清晰的模組結構和註釋
- **NFR4.3**: 遵循現有程式碼風格和架構

- **NFR5.1**: AI 回應使用繁體中文
- **NFR5.2**: 回應結構化,易於閱讀

## Constraints & Assumptions

### 技術限制

1. **模型限制**
   - 使用 qwen2.5:7b,上下文視窗有限(需控制提示詞長度)
   - 模型為本地部署,受硬體資源限制
   - 模型不支援聯網,僅能使用提供的資料

2. **資料限制**
   - 依賴現有 API 提供資料
   - 部分 API 可能返回模擬資料(需逐步替換為真實資料)
   - 資料更新頻率依賴各子系統

3. **前端整合限制**
   - 需與現有 ControlCenter.tsx 和 RAGChatbot 元件相容
   - 遵循現有的 API 呼叫模式和錯誤處理

### 假設條件

1. **技術假設**
   - Ollama 服務穩定運行於 localhost:11434
   - qwen2.5:7b 模型已經下載並可用
   - Python 後端環境已配置完成

2. **業務假設**
   - 管理員具備基本的交通管理知識
   - AI 建議作為輔助工具,最終決策由人類做出
   - 不需要即時多語言支援(僅繁體中文)

3. **資料假設**
   - 震波偵測資料準確且即時
   - 預測模型(MT-STNet)已訓練並可用
   - 交通站點資料涵蓋主要高速公路

## Out of Scope

### 明確不包含的功能

1. **多語言支援**
   - 本階段僅支援繁體中文
   - 未來可擴展英文或其他語言

2. **歷史對話持久化**
   - 對話僅保留在記憶體中
   - 不儲存到資料庫或檔案系統
   - 使用者刷新頁面後對話歷史清空

3. **複雜的權限管理**
   - 本階段不實作細緻的角色權限
   - 未來可加入管理員、分析師、觀察者等角色

4. **自動執行管制措施**
   - AI 建議不會自動執行
   - 必須由管理員手動確認並執行
   - 不整合實際的交通控制系統 API

5. **進階 AI 功能**
   - 不包含 AI 模型訓練或微調
   - 不包含多模態輸入(圖片、語音)
   - 不包含 AI Agent 自主行動

6. **即時協作功能**
   - 不支援多人同時對話
   - 不支援對話共享或轉發
   - 不支援 AI 建議的版本控制

## Technical Architecture

### 系統架構

```
前端 (ControlCenter.tsx)
    ↓
    ├─→ RAGChatbot 元件 ──→ /api/admin/chat
    └─→ AI 建議面板 ──────→ /api/admin/ai-recommendations
                              ↓
                    AdminOllamaRouter (FastAPI)
                              ↓
                    AdminOllamaClient
                              ↓
                        Ollama Service (qwen2.5:7b)
                              ↑
                        System Data Sources
                    ┌─────────┼─────────┐
                    ↓         ↓         ↓
            Traffic API  Shockwave  Prediction
```

### 模組設計

1. **admin_ollama_client.py**
   - 類別: `AdminOllamaClient`
   - 方法:
     - `generate_management_advice()`: 生成管理建議
     - `analyze_traffic_situation()`: 分析交通狀況
     - `generate_recommendations()`: 生成結構化建議

2. **admin_chat.py (API Router)**
   - 端點:
     - `POST /api/admin/chat`: 聊天對話
     - `POST /api/admin/ai-recommendations`: 生成建議
     - `GET /api/admin/ollama-status`: 檢查服務狀態

3. **提示詞檔案 (可選)**
   - `config/admin_prompts.yaml`: 提示詞配置
   - 支援動態載入和更新

| 資料來源變更 | 低 | 中 | 使用資料驗證和版本管理 |

### 術語表

- **震波 (Shockwave)**: 交通衝擊波,指交通流突然減速或停滯的現象
- **匝道管制 (Ramp Metering)**: 控制匝道車輛進入主線的速率
- **壅塞程度 (Congestion Level)**: 交通擁擠的百分比指標
- **信心度 (Confidence)**: AI 建議的可信度評分(0-1)
- **RAG**: Retrieval-Augmented Generation,檢索增強生成
